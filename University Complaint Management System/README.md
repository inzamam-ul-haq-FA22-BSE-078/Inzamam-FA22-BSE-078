<h3>App info</h3>
<h2>Workflow and Functionalities</h2>

<p>The workflow and functionalities present in the project are described as follows:</p>

<ul>
  <li><strong>Dashboard Screens:</strong> The app features a total of 5 dashboard screens: Student, Advisor, HOD, Director, and Admin.</li>
  <li><strong>Supabase Database:</strong> We utilize the Supabase database, which provides real-time notifications for changing complaint statuses. This functionality makes it highly preferable compared to other options.</li>
  <li><strong>Color Scheme:</strong> The app uses a blue and purple color scheme that aligns with our university logo, enhancing its visual appeal.</li>
  <li><strong>Total Screens:</strong> The project includes 11 screens: 5 for different dashboards, along with Theme Provider, Settings, Complaint Timeline, New Complaint, and Main file.</li>
  <li><strong>Dependencies:</strong> Various dependencies are included in the .yaml file to support animations, icons, and the ability to upload Excel files for user entry by the admin.</li>
  <li><strong>Student Dashboard Features:</strong> This screen allows users to add new complaints, receive real-time notifications of complaint status changes, view complaint timelines, check current complaint statuses, apply filters on complaints, access a side menu, and adjust settings to change colors and fonts.</li>
  <li><strong>Advisor Dashboard Features:</strong> This dashboard displays all complaints made, serving as the first step in resolving them. It includes filters for pending and solved complaints, a comprehensive complaint list, complaint timeline views, and three key functionalities: changing status to solved, rejected, or escalated to HOD. It also features a side menu for profile and logout, plus settings for font and color adjustments in the app bar.</li>
  <li><strong>HOD Dashboard Features:</strong> Complaints solved or rejected by the advisor are not shown here; only those escalated to HOD are displayed. It offers similar functionalities like profile, settings, filters, complaint timeline views, and three buttons for solved, rejected, or escalated to Director statuses.</li>
  <li><strong>Director Dashboard Features:</strong> If issues remain unresolved by the advisor and HOD, they escalate to the Director, who has the authority to resolve or reject complaints. The dashboard includes a complaint timeline, filters, settings, and a side menu with the user's name, email, and logout button.</li>
  <li><strong>Admin Dashboard Features:</strong> The admin screen includes a side menu with name, email, and logout options, plus settings for font and color adjustments. It also provides a system overview of the number of students, batch advisors, and HODs, and allows uploading Excel files with user data to the user table.</li>
  <li><strong>Notification System:</strong> Changing the status of a complaint by any batch advisor, HOD, or Director triggers a notification message on the related student's dashboard that submitted the complaint.</li>
  <li><strong>Complaint Timeline Screen:</strong> This screen displays the complete data and the entire transfer path of complaints, indicating who ultimately resolved them.</li>
  <li><strong>Settings Screen:</strong> Available across all dashboards, this screen allows adjustments to font size, app bar color, and body color.</li>
  <li><strong>Visual Enhancements:</strong> The app incorporates amazing animations, box shadows, icons, and other visual elements for a polished look.</li>
  <li><strong>Performance:</strong> The entire app functions properly and efficiently, ensuring a smooth user experience.</li>
  <li><strong>Database Structure:</strong> The app uses two tables: 'users' for authentication and directing to the relevant dashboard, and 'complaints' for tracking and resolving issues, forming the core of the complaint management system.</li>
</ul>

<p>The app stands out as one of the best works with a wide range of functionalities and robust management capabilities for a complaint management system. It is highly preferable for university-level use. However, there is potential for further improvements in the future to enhance its effectiveness for users.</p>
